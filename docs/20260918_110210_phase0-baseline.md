## Phase 0 implementation

- Added `DiagnosticSessionContext`, shared by the native gateway, TTS player, capture engine, energy VAD, Silero VAD, and native barge-in logs.
- Each voice/capture run gets one `diagnostic_session_id`; it is reused across playback start, PCM writes, capture start, VAD transitions, barge-in state transitions, and status snapshots.
- Microphone and gateway status maps now expose `diagnosticSessionId` metadata.
- Capture startup logs now include output route types, Android mode, `MIC` capture source, audio session ID, and AEC/NS supported/created/enabled state.
- TTS startup logs now include `USAGE_MEDIA` and `CONTENT_TYPE_SPEECH` metadata.
- The existing PCM policy remains explicit-only: diagnostic PCM capture is finite, app-private under `context.filesDir/openwakeword_diagnostics`, is not sent over the RN bridge, and has an explicit delete path. Normal capture and metadata diagnostics retain no PCM files.
