# Step-by-step process to pass LangGraph phases 0, 3, 7, 8, and 9

**Date:** 2026-09-25  
**Plan:** [`plan.md`](plan.md)  
**Status of this file:** operational runbook. It does not change application code.

Phases 1, 2, 4, 5, and 6 already passed their implementation gates. These remaining gates fail because live evidence is missing (0, 3, 9), one action path is unfinished (7), or the classifier is correctly deferred (8). Do the work in this order. **Do not enable canary or `on` until Phase 0 and Phase 7 both pass.**

```text
Phase 7 code (no phone)     ──┐
                              ├──► Phase 3 live shadow ──► Phase 8 confirm deferred ──► Phase 9 canary
Phase 0 physical baseline ───┘
```

Phase 8 does not need a classifier. It “passes” when you re-measure and still have no safe-accuracy gap.

---

## What “PASS” means for each remaining phase

| Phase | Pass condition | Phone required? |
|---|---|---|
| **0 Freeze baseline** | One complete `phase0_live_driver.py` run with `outcome=complete`, ≥20 valid turns, 0 exclusions, 0 barge-in anomalies, paired backend P50/P95 for three latency metrics, all required route categories, and confirmed create + cleanup writes | Yes |
| **3 Shadow** | `ROUTER_MODE=shadow` on a sampled cohort; privacy-safe `router.shadow.observation` logs exist; disagreements reviewed; no extra user-visible TTS/tools/writes | Yes, after Phase 0 |
| **7 General/action** | `MEMORY_ACTION` forget is wired to the existing proposal/confirmation path; general/task still skip RAG; no mutation before approval or twice; cancel/commit/retry/disconnect proofs exist | No |
| **8 Classifier** | Re-run the assessment. If deterministic rules still match labeled cases with zero false executable routes, keep **NOT TRIGGERED / deferred** and treat the gate as satisfied | No |
| **9 Rollout** | Canary by stable user hash, performance review vs Phase 0, in-flight rollback drill, post-cutover physical voice check. Lint/format failures fixed or explicitly dispositioned | Yes, after 0 and 7 |

## Phase 0 — freeze the legacy physical baseline

This is the blocker for 3 and 9. The router must stay **off**. Previous Oppo runs did **not** pass: the phone was connected, then the harness aborted on loudspeaker barge-in (`no_safe_acoustic_path`) or a longer manual capture lacked route labels, paired clocks, tokens, and write safety.

### 0.1 Decide the acoustic path (required)

Loudspeaker on Oppo CPH2527 currently emits `barge_in_degraded` with `no_safe_acoustic_path` (`reference_ready=false`, `aec_healthy=false`). The live driver treats that as a fatal anomaly and stops the whole run. That is why phone tests looked “the same.”

**Use wired headphones or earpiece for this baseline.** Keep the laptop speakers away from the phone mic. Wait until phone TTS fully finishes before the next prompt.

Do **not** try to pass Phase 0 on loudspeaker until either:

- the known barge-in defect is fixed, or
- the harness is changed to record `no_safe_acoustic_path` as the known defect instead of aborting the measurement.

Plan.md already says barge-in is a separate defect and must not block router measurement. Headphones are the no-code way to get a valid baseline now.

### 0.2 Host and device prerequisites

On the Windows machine that will run the harness:

1. Plug in the test phone with USB debugging authorized.
2. Confirm ADB can create its key directory. If `adb devices -l` prints `Cannot mkdir '\.android': Permission denied`, set a writable `HOME` first:

```powershell
$env:HOME = $env:USERPROFILE
& "$env:ANDROID_SDK_ROOT\platform-tools\adb.exe" devices -l
```

Or use [`scripts/adb_phase4.ps1`](scripts/adb_phase4.ps1).

3. Default harness identity is Oppo **CPH2527**, serial **`9b0ea196`**. Another phone needs `--device-serial` and `--device-model`.
4. Grant microphone permission to `com.voiceaipoc`.
5. Start Metro on `127.0.0.1:8081`.
6. Start the backend so both succeed:
   - `GET http://127.0.0.1:8000/health` → `{"status":"ok"}`
   - `GET http://127.0.0.1:8000/ready` → HTTP 200, `status=ready` for Postgres, Redis, LLM, **TTS**, embedding, and reranker.
7. Confirm Windows has a local speech voice (the driver uses `System.Speech`, not cloud TTS for prompts).
8. Sign the app into the **disposable test account**. Confirm it is disposable before any write prompt.

Router flags for this run must be:

```text
ROUTER_MODE=off
ROUTER_COHORT_PERCENT=0
```

Leave memory retrieval at the current local profile (`inject` is fine). GraphRAG stays `off`.

### 0.3 Seed account data the script expects

[`backend/scripts/phase0_live_manifest.json`](backend/scripts/phase0_live_manifest.json) asks:

- “What is my Phase Zero test drink?” → that fact must already be saved on the disposable account.
- “What is my Phase Zero test color?” → must **not** exist (missing-memory case).
- Later: “Remind me to perform Phase Zero test cleanup tomorrow at 9 AM.” then spoken **Yes**, then “Mark the Phase Zero test cleanup task complete.” then **Yes**.

If the drink memory is missing, the turn may still complete, but the memory-hit category is weaker. Seed the drink memory once before the run. Do not leave extra “Phase Zero test cleanup” tasks from aborted runs; delete them first.

### 0.4 Run the automated 20-turn capture

From the repository root, with the venv that has the backend installed:

```powershell
$env:PYTHONPATH = "backend"
$env:HOME = $env:USERPROFILE
.\.venv\Scripts\python.exe backend\scripts\phase0_live_driver.py --disposable-account-confirmed
```

Other phone:

```powershell
.\.venv\Scripts\python.exe backend\scripts\phase0_live_driver.py `
  --disposable-account-confirmed `
  --device-serial <serial> `
  --device-model <model>
```

What the driver does, in order:

1. Checks ADB device, reverse `tcp:8000` and `tcp:8081`, mic permission, `/health`, `/ready`, TTS URL, local speech.
2. Starts the live event collector (backend trace + Android logcat).
3. Waits for a voice WebSocket and heartbeat (`server.pong`).
4. Speaks each scripted prompt from the laptop; the phone mic is the listener.
5. For write cases, checks Redis pending confirmation **before** speaking Yes, then checks the database after commit/cleanup.
6. Writes:
   - `logs/phase0_physical_baseline_<run_id>.jsonl`
   - `logs/phase0_physical_baseline_rows_<run_id>.jsonl`
   - `logs/phase0_physical_baseline_summary_<run_id>.json`
   - `docs/<run_id>_phase0_automated_physical_baseline.md`

Quiet room. Do not talk over the laptop. Do not start a second session. If phone TTS is still playing, the driver will refuse the next prompt (`auto6` failed that way). If WebSocket drops, the run is invalid (`auto8`).

### 0.5 Gate checklist (all must be true in the summary JSON)

Open `logs/phase0_physical_baseline_summary_<run_id>.json` and confirm:

- [ ] `"outcome": "complete"` (not `aborted`)
- [ ] `"valid_completed_physical_turns"` ≥ 20
- [ ] `"excluded_turns"` = 0
- [ ] `"lifecycle_anomaly_count"` = 0
- [ ] `"router_mode": "off"`, `"router_cohort_percent": 0`, `"langgraph_router_calls": 0`
- [ ] These metric counts are each ≥ 20:
  - `backend_speech_end_to_first_text`
  - `backend_speech_end_to_first_audio`
  - `backend_complete_turn`
- [ ] Rows include every category:
  - `general_llm`
  - `current_time`
  - `current_date`
  - `structured_task_read`
  - `structured_reminder_read`
  - `memory_query`
  - `memory_query_missing`
  - `confirmed_task_write`
  - `confirmed_task_cleanup`
- [ ] Case `P0-LIVE-013`: pending confirmation verified before Yes; `write_attempts=1`, `confirmed_writes=1`, `write_commits=1`, `unconfirmed_writes=0`
- [ ] Case `P0-LIVE-016`: `cleanup_verified=true` with the same confirmation/write rules
- [ ] Whole run: exactly 2 write attempts, 2 confirmed writes, 0 unconfirmed, 0 duplicates
- [ ] Per-category `route_totals` has model/retrieval/tool counts (tokens may be `n/a` only if the provider omitted usage; prefer `provider_usage_reported`)

If any item fails, **do not** invent P50/P95 from mixed-clock traces or from `logs/latency_trace.jsonl`. Re-run the driver. Partial captures (`auto1`–`auto8`) do not count.

### 0.6 After a passing run

1. Copy the numeric complete-turn P50/P95 into the Phase 0 baseline note. Those become the Phase 9 regression ceilings (P50 × 1.02, P95 × 1.05).
2. Keep the known loudspeaker barge-in defect **separate**. Do not mark physical barge-in PASS from this headphone baseline.
3. Record rollback owner (already: Bhoomi; backup: backend lead).
4. Check the Phase 0 box in [`plan.md`](plan.md).

**Phase 0 PASS.** Router stays off.

## Phase 7 — finish general/action paths (can start before the phone is back)

This is a **code** gate. Phone tests will not pass it.

### 7.1 What is already done

- `GENERAL_LLM` and `TASK_ACTION` skip RAG; covered by tests.
- “Remind me to …” is `create_task` with confirmation; no push-notification claim.
- `memory_save` still uses the existing explicit proposal bypass.
- Cancel-before-commit unit coverage exists.
- `resolve_forget_target()` exists in [`backend/app/memory/forget_resolution.py`](backend/app/memory/forget_resolution.py) but is **not called** by the gateway.

### 7.2 Wire `MEMORY_ACTION` forget (required)

Today, in canary/on, forget always abstains in [`backend/app/websocket/gateway.py`](backend/app/websocket/gateway.py) (`I can't safely identify which saved memory…`) and never creates a confirmation.

Implement this and nothing else as a second write path:

1. On `MEMORY_ACTION` + `memory_forget`, call `resolve_forget_target(db, user_id=authenticated owner, transcript=…)`.
2. **`unique`:** build a `memory_forget` tool call with that UUID only. Send it through existing `ToolExecutor` (scopes, confirmation, audit, idempotency). Do not run RAG. Do not let the main LLM invent an ID.
3. **`ambiguous`:** speak a clarification. No proposal, no mutation.
4. **`no_match`:** bounded abstain (current wording is fine). No LLM guess, no retrieval.
5. Keep `memory_save` on the existing `build_explicit_memory_save_call` proposal path until forget is proven; then optionally route save the same way. Do not add a second memory writer.
6. Recheck cancellation and authorization immediately before the confirmed commit. After commit, cancellation must not undo the write.

### 7.3 Tests that must exist before claiming Phase 7 PASS

Add or extend tests (gateway/tool/confirmation; no full app rebuild required):

- [ ] Unique owned active row → one `memory_forget` proposal, confirmation required, zero RAG, zero main-LLM fallback after the action is claimed
- [ ] Ambiguous / inactive / foreign row → no proposal, no mutation
- [ ] Spoken Yes executes once; second Yes / replay does not write again
- [ ] Disconnect and resume: pending confirmation still owned by the same user/device; no duplicate commit
- [ ] Cancel after handler success but before gateway commit → rollback, no row change
- [ ] Cancel after commit → write remains; no undo
- [ ] Informational “How do I forget a saved memory?” stays `GENERAL_LLM`, not a write
- [ ] Existing Phase 7 corpus [`backend/tests/fixtures/phase7_action_acceptance_v1.json`](backend/tests/fixtures/phase7_action_acceptance_v1.json) still matches routes

Run focused tests, then targeted Ruff on touched files. Do not treat the 75-case deterministic corpus as Phase 7 PASS by itself.

### 7.4 Record Phase 7 PASS

Update [`plan.md`](plan.md) Step 7 checkboxes and add a work note under `docs/` (dated `_phase7_memory_forget_wiring.md`). Router still stays off until Phase 9.

**Phase 7 PASS.**

## Phase 3 — live shadow comparison (after Phase 0)

Implementation is already in the gateway and [`backend/app/routing/service.py`](backend/app/routing/service.py). It does not run while `ROUTER_MODE=off`.

### 3.1 Enable observation only

1. Keep the same backend, phone, and disposable account used for Phase 0.
2. Change settings (restart/reload backend):

```text
ROUTER_MODE=shadow
ROUTER_COHORT_PERCENT=100
```

Use 100% only on the disposable test user. Production stays 0 until Phase 9.

3. Confirm `/ready` still healthy and the gateway still answers through the **legacy** path (no change in TTS/tools from the router).
4. Run a labeled sample of completed STT turns (the Phase 0 prompt set is enough). Include time, date, schedule read, memory, general, remind-me, and forget/save if Phase 7 is done.

### 3.2 What must appear in logs

Each sampled turn should emit `router.shadow.observation` with:

- `session_id`, `turn_id`, `response_id`
- `shadow_route`, `legacy_route`, disagreement flag/category
- `target_tool` / `action_domain` (no arguments)
- latency, status/fallback
- **no** transcript, memory content, or secrets

Shadow must not send WebSocket/TTS events, execute tools, call a model, or repeat retrieval.

### 3.3 Disagreement review

1. Group disagreements by category (clock vs schedule, informational vs action, memory vs general, mixed).
2. Update deterministic rules and the frozen corpus **before** canary if a safety disagreement appears (false executable route).
3. If rules stay safe and only abstain more than the legacy tool selector, that is acceptable; do not add a classifier yet (see Phase 8).
4. Bound load: existing 250 ms timeout and `ROUTER_SHADOW_MAX_CONCURRENT` (default 4). Honor memory opt-out even in shadow.

5. Set flags back if needed:

```text
ROUTER_MODE=off
ROUTER_COHORT_PERCENT=0
```

until Phase 9.

**Phase 3 PASS** when the sample exists, disagreements are reviewed, and there is evidence of zero user-visible shadow side effects.

## Phase 8 — classifier (expected result: still deferred)

Do not implement a semantic classifier unless Phase 3 shows a persistent safe-accuracy gap.

### 8.1 Re-measure (required once after Phase 7 corpus updates)

From repo root:

```powershell
$env:PYTHONPATH = "backend"
.\.venv\Scripts\python.exe backend\scripts\phase8_classifier_assessment.py
```

Pass criteria for **deferred / not triggered**:

- Expected deterministic route/target/clarification matches = all labeled cases
- False executable deterministic routes = 0
- No live classifier was added

Current recorded result: 67/67 matches, 20 ambiguous abstentions, 0 false executable routes. The offline named-tool selector is **not** live shadow evidence.

### 8.2 Only if a classifier later becomes justified

Then, and only then:

1. Separate flag, bounded input/tokens/deadline.
2. Skip obvious clock and pending Yes/No.
3. Pydantic-validate the proposed route; allow-list tools; fail closed.
4. Benchmark vs frozen corpus and the current provider, including adversarial STT text.
5. Classifier output must never authorize a write.

Until that gap exists, mark Step 8 in [`plan.md`](plan.md) as **NOT TRIGGERED / deferred** and treat the phase as closed for the initial router release.

**Phase 8 complete (deferred).**

## Phase 9 — canary, measure, rollback

Do not start this until Phase 0 PASS and Phase 7 PASS. Phase 3 review should be done first. Phase 8 should still be deferred unless shadow forced a classifier.

### 9.1 Release blockers to fix or disposition

Record current check results in a Phase 9 note. Known items from the last readiness pass:

- Backend Ruff lint: should already pass.
- Repo-wide `ruff format --check backend`: remaining unformatted files — format or list as explicit non-blockers with owners.
- Frontend `npm run check`: TypeScript error in `frontend/__tests__/phase3.test.ts` (expression inferred as `never`) — fix or disposition.
- Frontend Prettier: remaining unformatted files — same.
- UI secret-scan false positive on `testID="task-date-input"` — keep documented as false positive.
- Privacy: routine final-transcript logs must stay IDs/timing only (already changed; keep the regression test).

Do not enable production canary while critical type/lint failures are unddispositioned.

### 9.2 Enable canary (not `on`)

1. Set:

```text
ROUTER_MODE=canary
ROUTER_COHORT_PERCENT=5
```

Cohort is a stable hash of authenticated `user_id` (`bucket < percent`). Restart/reload backend.

2. Verify `/health` and `/ready`.
3. Keep GraphRAG off. Do not widen past 5% in this step.
4. Watch: route disagreements, main-model calls/tokens per route, embedding/reranker/retrieval per route, P50/P95 vs Phase 0, STT-to-first-audio, cancellation, stale TTS, writes.

### 9.3 Canary acceptance numbers

Safety (absolute):

- 100% on critical intent distinctions from the frozen corpus
- 0 unconfirmed writes
- 0 duplicate writes
- 0 cross-user leakage
- grounded memory no-result (no guessing LLM)
- no WebSocket/TTS protocol regression

Latency (from Phase 0, now that it exists):

- Rule decision p95 ≤ 50 ms
- Added speech-end-to-first-text/audio p95 ≤ 100 ms vs legacy
- Complete-turn regression p50 ≤ 2%, p95 ≤ 5%
- Deterministic clock/control/general routes: no extra main-model or retrieval/embedding calls

Do not invent cost per 100 turns unless provider pricing is verified.

### 9.4 In-flight rollback drill (required)

While canary is live, with a pending confirmation **not** executing:

1. Set `ROUTER_MODE=off` (there is no `LANGGRAPH_ROUTER_MODE`).
2. Reload/restart backend if settings are process-cached.
3. `/health` and `/ready` succeed.
4. Gateway smoke: Yes/No confirmation still works on the **legacy** path.
5. Confirm no duplicate or unexpected pending writes; task/reminder/memory ownership unchanged.
6. Record the drill in the Phase 9 report.

Owner: Bhoomi. Backup: backend lead / designated developer.

### 9.5 Physical voice regression after canary (same phone)

Same device as Phase 0. Headphones still recommended until barge-in is fixed.

Check: time/date, schedule read, memory hit/miss, remind-me confirmation, forget confirmation (Phase 7), barge-in **not** attributed as a router pass. Track loudspeaker `no_safe_acoustic_path` as the existing defect.

### 9.6 Widen only after the report

Only after the canary report and rollback drill pass:

```text
ROUTER_MODE=on
ROUTER_COHORT_PERCENT=100
```

Keep `off` as the kill switch.

**Phase 9 PASS.**

- Do not reuse `logs/latency_trace.jsonl` or aborted `auto1`–`auto8` summaries as P50/P95.
- Do not mix Android monotonic timestamps with backend `perf_counter` timestamps.
- Do not copy transcripts or personal memory into reports.
- Do not treat the 75/75 deterministic corpus as Phase 0, 3, or 9 PASS.
- Do not add a Phase 8 classifier “just in case.”
- Do not add LangGraph `interrupt()` / a second confirmation store (Phase 10) until 0–9 are stable.
